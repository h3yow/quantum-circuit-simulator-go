# 本地量子线路模拟器（Go）

一个零依赖的本地纯态（state vector）量子线路模拟器：从文本描述解析电路，
按顺序演化量子态、支持中途测量与基于经典比特的条件操作，并进行可复现的批量采样。

- 同一个线路在**相同随机种子与运行次数下结果完全一致**（与并发调度无关）；
- 每个 shot 使用独立态向量与由 `(seed, shot)` 派生的独立 PCG 随机流，**并发复用互不污染**；
- 解析与运行期错误都返回带类别的 `*qsim.CircuitError`，可程序化区分失败原因；
- 量子比特数超限时返回明确的 `RESOURCE_EXHAUSTED` 错误，而不是 OOM 崩溃。

## 快速开始

```go
import qsim "github.com/h3yow/quantum-circuit-simulator-go/qsim"

src := `QUBITS 2
CBITS 2
H q[0]
CX q[0], q[1]
MEASURE q[0] -> c[0]
MEASURE q[1] -> c[1]
`
sim := qsim.New(0) // 0 表示使用默认资源上限（24 量子比特）
res, err := sim.Run(src, qsim.Options{Shots: 1000, Seed: 42})
// res.Counts: map[int]int，键为经典寄存器编码（c[0] 为最低位）
// 例如 Bell 电路只会出现 0(00) 与 3(11)
```

也可以先 `qsim.Parse(src)` 得到 `*Circuit`，再用 `sim.RunCircuit(c, opts)` 复用。

## 电路描述格式

行导向文本，`//` 之后为注释，空行忽略。角度单位为弧度。

### 比特声明

| 语句 | 含义 |
| --- | --- |
| `QUBITS n` | 声明 n 个量子比特 `q[0..n-1]`（初态 \|0⟩） |
| `CBITS n`  | 声明 n 个经典比特 `c[0..n-1]`（初值 0） |

两类声明都可出现多次，区间累加；**与已有区间重叠即报 `DUPLICATE_DECL`**。

### 门操作

通用形式：`门名[(参数, ...)] q[i], q[j], ...`（括号外逗号可有空格）。

| 门 | 参数 | 比特数 | 说明 |
| --- | --- | --- | --- |
| `I X Y Z H S SDG T TDG` | 无 | 1 | 常见单比特门（SDG/TDG 为 S/T 的逆） |
| `RX(θ) RY(θ) RZ(θ) P(φ)` | 1 个角度 | 1 | 旋转/相位门 |
| `CX`（别名 `CNOT`）、`CZ`、`SWAP` | 无 | 2 | qbits 顺序为 `控制位..., 目标位`，即 `CX q[0], q[1]` |
| `CCX`（别名 `TOFFOLI`） | 无 | 3 | qbits 顺序为 `控制1, 控制2, 目标` |

角度支持受限表达式：十进制数字、`pi`、一元负号、`+ - * /` 与括号，
例如 `RX(pi/2)`、`RZ(-(pi/4))`、`P(2*pi + 0.1)`。

矩阵约定：多比特门矩阵作用于复合空间，操作数中第一个量子比特对应复合下标高位。

### 测量

```
MEASURE q[k] -> c[j]
```

按当前态在 `q[k]` 上的测量概率（即该比特为 1 的所有基矢概率幅平方和）抽样，把 0/1 写入 `c[j]`，
并立即把未观测到的分支清零、整体归一化——**测量是坍缩性的，会改变后续状态**。

### 条件操作

```
IF (c[j]) <门> q[...]
```

当且仅当 `c[j] == 1` 时执行门（条件体目前只支持门，不支持嵌套测量/IF）。
由于条件依赖此前写入的经典比特，它自然地表达了"按中途测量结果分支"。
`IF (c[0])` 与 `IF ( c[0] )` 两种空格写法都支持。

## 错误类别

所有失败都返回 `*qsim.CircuitError`，通过 `Kind` 字段（或 `errors.As`）判断：

| Kind | 触发场景 |
| --- | --- |
| `SYNTAX` | 结构不完整/词法非法（缺箭头、缺括号、操作数不是 `q[k]` 等） |
| `UNKNOWN_OP` | 出现未注册的门名 |
| `DUPLICATE_DECL` | 重复声明同一量子/经典比特 |
| `OUT_OF_RANGE` | 比特下标超出已声明范围 |
| `INVALID_ARG` | 参数个数/取值错误、门比特数错误、同一操作内比特重复、Shots 非法等 |
| `RESOURCE_EXHAUSTED` | 态向量规模超过上限 |

错误带 1 基行号与中文说明，例如：
`UNKNOWN_OP (line 2): 未知的门操作 "NOPE"`。

## 测量与随机语义

- 每个 shot 从 \|0…0⟩ 开始独立演化；测量结果由当前态概率分布抽样。
- 随机源为 Go 的 PCG（`rand/v2`），shot *i* 使用 `PCG(seed, i)` 派生：
  - 相同 `Seed` + 相同 `Shots` + 相同电路 ⇒ **逐 shot 完全相同**的采样结果；
  - 不同 shot 的随机流互不相同；
  - 结果只取决于 `(电路, Seed, shot 序号)`，与并发执行顺序无关。
- `Result.Counts` 聚合全部 shot 结束时经典寄存器的值；
  `Result.Measurements` 记录 **shot 0** 的测量事件序列（含量子比特、经典比特、测得值），
  便于解释中途测量与条件分支。

## 资源限制

n 个量子比特的稠密态向量需要 `2^n` 个 `complex128`（每幅度 16 字节）：

| n | 内存 |
| -- | -- |
| 20 | 16 MiB |
| 24（默认上限） | 256 MiB |
| 30 | 16 GiB |

- 默认上限 24；`qsim.New(maxQubits)` 可调整，单次运行还可用
  `Options.MaxQubits` 收紧。
- 超限在分配前直接返回 `RESOURCE_EXHAUSTED`（消息含所需幅度数与内存量级）。
- 另有约 16 GiB 的硬上限兜底，防止调用方把上限设得过大。

## 并发

`*qsim.Simulator` 创建后只读，可被任意多 goroutine 共享；每次 `Run`/`RunCircuit`
的态向量、经典寄存器、随机源均为调用局部变量，无共享可变状态。
测试以 `-race` 下数十个 goroutine 复现同种子结果来保证这一点。

## 本地验证

```bash
go build ./...
go vet ./...
go test ./...                 # 全部单测（日志含输入电路与判定依据）
go test -race ./...           # 含数据竞争检测的并发验证
go test ./... -v              # 查看每个用例打印的输入电路与判定依据
go test -run TestSimulator -v # 只跑模拟器语义/复现/并发用例
go test -run TestParse -v     # 只跑解析与错误类别用例
```

测试覆盖：

- 正常线路：Bell 纠缠分布、角度表达式、多比特门、条件分支；
- 异常线路：未知操作、越界、重复声明、语法不完整、参数错误（逐类别断言）；
- 语义：中途测量坍缩后影响后续门、条件分支按测量结果生效/不生效；
- 复现：同种子多次调用逐 shot 一致，不同种子独立分布；
- 资源：超过默认/自定义比特上限返回 `RESOURCE_EXHAUSTED`；
- 并发：`-race` 下多 goroutine 复用同一模拟器且与串行结果一致。
